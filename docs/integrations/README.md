# مركز تكاملات حاضر

هذه الطبقة هي الأساس الآمن لتكاملات نور، مدرستي، وحضوري عندما لا تتوفر واجهات API رسمية.

## المنجز حالياً

- سياسة موحدة لأتمتة المواقع الحكومية: متصفح مرئي، دخول وMFA يدويان، قائمة نطاقات HTTPS صريحة، معدل إجراءات محافظ، ومراجعة بشرية قبل أي كتابة.
- واجهة تكامل واحدة تفصل بين:
  - قراءة النظام الخارجي وفحص التغييرات.
  - استيراد تغييرات معتمدة إلى حاضر.
  - الكتابة إلى النظام الخارجي، وهي مسار مستقل ومغلق افتراضياً.
- محول أولي لكشف طلاب نور يقرأ جدولاً عربياً، يوحّد الأرقام العربية والفارسية، ويقارن الكشف بسجل حاضر.
- تصنيف كل طالب إلى: جديد، محدّث، مطابق، أو مفقود.
- منع حذف الطالب المفقود تلقائياً؛ يظهر كتغيير محظور يحتاج تحققاً يدوياً.
- إيقاف آمن عند صفحة تسجيل الدخول، كشف فارغ، تخطيط غير معروف، نطاق غير مصرح، أو رقم طالب مكرر.
- بصمة SHA-256 لمحتوى الكشف تكشف تغيّر البيانات دون حفظ HTML أو رابط الصفحة في المراجعة.
- اعتماد بشري من هوية جلسة موثوقة وصلاحية صريحة، مع اختيار التغييرات قبل حفظها محلياً.
- سجل تدقيق محلي محدود الحجم يحتفظ بالبيانات التشغيلية المسموح بها فقط.
- شاشة «مركز التكاملات» ضمن الإدارة تعرض حالة نور والمعاينة والاختيار الصريح وسجل التدقيق.
- نافذة Electron مستقلة ومرئية لنور، مع جلسة ذاكرة مؤقتة تُمسح عند إغلاقها أو تسجيل الخروج من حاضر، وحصر كل طلبات الشبكة في نطاقي نور والدخول الموحد الرسميين.
- التقاط صفحة كشف الطلاب الحالية للقراءة فقط؛ لا تُنفذ النافذة تسجيل دخول أو نقرات أو كتابة آلية.

## قواعد لا يجوز كسرها

- لا إخفاء لـ `navigator.webdriver` ولا تعديل لبصمة المتصفح.
- لا تبديل User-Agent بغرض التخفي.
- لا تجاوز CAPTCHA أو MFA أو أي تحدٍ أمني.
- لا تخزين لكلمات المرور أو رموز الجلسة أو HTML الخام.
- لا تشغيل خفي ولا ضغط سريع ولا محاولات عمياء.
- لا حذف تلقائي ولا كتابة جماعية دون مراجعة واعتماد بشري.
- عند تغيّر تخطيط المنصة يتوقف الموصل بدلاً من التخمين.

## حدود الربط الحي الحالي

تم ربط نافذة سطح المكتب الحقيقية للقراءة فقط، لكن المشروع لا يزال لا يحتوي عينة موثوقة وحديثة من صفحة كشف نور بعد تسجيل الدخول. لذلك لا يتنقل حاضر داخل نور ولا يضغط عناصر بالنيابة عن المستخدم: يسجل المستخدم الدخول وينتقل يدوياً إلى الكشف، ثم يقرأ حاضر جدولاً مكتمل الأعمدة ويتوقف إذا لم يتعرف على التخطيط. يجب إجراء التجربة الأولى بحساب مصرح وصفحة منزوعة البيانات أو ضمن مدرسة تجريبية، ومقارنة النتيجة يدوياً قبل الاستخدام التشغيلي.

## طريقة التجربة الآمنة

1. شغّل نسخة سطح المكتب وافتح الإدارة ← مركز التكاملات.
2. اضغط «فتح جلسة نور الآمنة» وسجّل الدخول بنفسك، بما في ذلك أي تحقق إضافي.
3. انتقل يدوياً إلى صفحة كشف الطلاب داخل نور وانتظر اكتمال تحميلها.
4. عد إلى حاضر واضغط «فحص كشف الطلاب الحالي».
5. راجع كل صف؛ لا يكون أي تغيير محدداً افتراضياً، ولا يمكن اعتماد الحذف أو الصفوف المحظورة.
6. حدد الإضافات أو التحديثات المطلوبة ثم اعتمدها. الحفظ في هذه المرحلة داخل حاضر فقط.

## الخطوات التالية

1. اختبار تجريبي على كشف منزوعة بياناته، ومقارنة النتائج يدوياً.
2. تثبيت عقد تخطيط نور بعينات اختبار منزوعة البيانات عند اختلاف أنواع الكشوف.
3. إطلاق استيراد كشف الطلاب لمستخدمين محدودين مع زر إيقاف فوري.
4. بناء قراءة تحضير مدرستي، ثم قراءة حضور المعلمين من حضوري وفق السياسة نفسها.
5. عدم تفعيل أي كتابة خارجية إلا بعد موافقة الجهة، واختبار تجريبي، وسجل مراجعة واضح.

قبل تفعيل الربط الحي يجب أيضاً نقل سجل التدقيق من `localStorage` إلى outbox دائم وذري، وتنفيذ الحفظ السحابي بمقارنة-and-swap أو معاملة تمنع الكتابة فوق تعديل متزامن. السجل المحلي الحالي تشغيلي للمرحلة التجريبية، وليس سجلاً جنائياً غير قابل للعبث.

## حضوري ومدرستي — مزامنة التقارير (سبتمبر 2026)

أصبح مركز التكاملات يتيح مراجعة واستيراد حضور المعلمين من حضوري وحالة تحضير الدروس من مدرستي. مصدر البيانات في هذه المرحلة ملف Excel/CSV أو جدول منسوخ من المتصفح يُلصق مع عناوينه. هذا **عقد استيراد داخلي** قابل للاختبار، وليس إثباتاً لمطابقة كل تقرير رسمي أو اتصالاً حياً أو مزامنة مجدولة مع المنصتين.

### الاستخدام

1. أضف المعلمين في إدارة المعلمين بمعرفات ثابتة تطابق التقرير. احتفظ بالأصفار البادئة كـنص في Excel.
2. في مركز التكاملات اختر حضوري أو مدرستي، ثم نزّل القالب لعرض الأعمدة المقبولة.
3. ارفع التقرير (حتى 5MB و10000 صف)، أو الصق جدولاً بعناوين الأعمدة مفصولاً بفواصل أو علامات تبويب.
4. طابق المدرسة والفترة بنفسك. التاريخ المطلوب ميلادي `YYYY-MM-DD`؛ لا يُحوّل التاريخ الهجري أو تاريخ Excel الرقمي تخميناً.
5. راجع القيم قبل/بعد وحدد السجلات المطلوبة. لا يحدد النظام سجلات افتراضياً ولا يعيد استيراد السجلات المطابقة.
6. اضغط اعتماد. تعرض اللوحة آخر اعتماد والسجلات المحفوظة، حتى بعد إعادة فتحها.

| المنصة | الأعمدة |
|---|---|
| حضوري | معرف المعلم أو اسم المعلم، التاريخ، حالة الحضور، دقائق التأخر (اختياري) |
| مدرستي | معرف المعلم أو اسم المعلم، التاريخ، الحصة، المادة، الصف، الفصل، حالة التحضير |

الحضور: `حاضر / متأخر / غائب` أو `present / late / absent`. التحضير: `محضر / غير محضر` أو `تم التحضير / لم يتم التحضير` أو `prepared / not-prepared`. تُوحّد الأرقام العربية والفارسية. إذا ورد الاسم والمعرف معاً، يجب أن يتطابقا مع المعلم نفسه. الحالات الأخرى، ومنها «لا توجد بصمة» والإجازات، تُرفض ولا تتحول تلقائياً إلى غياب.

### ضمانات الحفظ وحدود التشغيل

- حضوري يحدّث سجل حضور المعلمين الذي تستخدمه اقتراحات الانتظار. مدرستي يحفظ تحضير الدروس في جدول مستقل؛ عدم التحضير لا يعني غياب المعلم.
- لا تُحذف السجلات غير الواردة في التقرير، ولا يتغير الجدول الأسبوعي باستيراد تقرير التحضير.
- يُرفض التقرير كاملاً عند معرف مجهول/ملتبس أو معلم غير نشط أو صف مكرر أو حالة/تاريخ غير معروف.
- كل السجلات المختارة وحدث التدقيق التشغيلي والإصدار تحفظ في معاملة IndexedDB واحدة. فشل أي منها يلغي المعاملة كلها.
- يتطلب الحفظ جلسة المدير نفسها التي أجرت المعاينة، ومعاينة غير مستخدمة لم تتجاوز 15 دقيقة. أي تعديل في بيانات المعلمين بعد المعاينة يرفض الحفظ حتى إعادة الفحص؛ المقارنة داخل المعاملة تمنع السباق بين التبويبات.
- ترقية قاعدة بيانات المعلمين إلى الإصدار 3 تضيف جدول التحضير وتحافظ على البيانات القديمة.
- التخزين محلي وفق نطاق قاعدة بيانات وحدة المعلمين الحالية، وليس عزلاً سحابياً متعدد المدارس. لا تُنشر هذه الميزة كربط حي متعدد المدارس قبل إضافة نطاق مدرسة موثوق وجداول سحابية بسياسات RLS.
- سجل أحداث الاستيراد النهائي موجود مع بيانات المعلمين في IndexedDB؛ سجل دورة المعاينة القديم في `localStorage` يبقى تشغيلياً وغير حصين ضد العبث.

### الربط المباشر المتبقي

نحتاج تقريراً رسمياً منزوع البيانات أو عينة مصرحاً بها من الصفحة بعد الدخول، أو عقد API رسمي، لتثبيت عناوين الأعمدة والحالات ونطاقات المصادقة والتنقل. لم نضف نقاط API تخمينية أو آليات تسجيل بصمة نيابة عن الموظف أو كتابة خارجية. يمكن توصيل مصدر API/متصفح موثّق لاحقاً إلى `inspectRows` مع إبقاء نفس دورة المراجعة والحفظ.

راجعنا صفحات الوزارة العامة لتحديد وظيفة المنصتين، لا لاشتقاق عقد API:
- [تقارير مدرستي وإحصائياتها](https://www.moe.gov.sa/ar/knowledgecenter/eservices/pages/reportsandstatistics.aspx).
- [تحضير الدروس في مدرستي](https://madrasatibeta.moe.gov.sa/services/lesson-preparation?Language=1).
- [بوابة حضوري](https://hather-ui.moe.gov.sa/).
