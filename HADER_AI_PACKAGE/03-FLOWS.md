# HADER AI PACKAGE - تدفقات العمل

## 03-FLOWS.md

### 1. تدفق تسجيل الحضور (Attendance Flow)
#### A. عبر الكشك (Kiosk Mode)
1.  يقوم الطالب بمسح تذكرته (QR Code) أمام الكاميرا.
2.  يتحقق النظام من صحة الرمز (Valid Student ID).
3.  يتم تسجيل وقت الحضور الحالي تلقائياً.
4.  يتم تحديد الحالة:
    *   قبل وقت التأخير المحدد -> **حاضر (Present)**.
    *   بعد وقت التأخير -> **متأخر (Late)** مع حساب دقائق التأخير.
5.  يتم تخزين السجل في قاعدة البيانات المحلية (LocalForage).
6.  تظهر رسالة تأكيد للطالب (الصفحة الخضراء/الصفراء).
7.  يعود الكشك لوضع الاستعداد (Reset) خلال 3 ثوانٍ.

#### B. الحضور اليدوي (Manual Entry)
1.  يدخل المشرف/المراقب إلى صفحة "المراقب" (Watcher) أو "الإشراف" (Supervision).
2.  يختار الصف (Grade) والفصل (Section).
3.  تظهر قائمة الطلاب.
4.  ينقر على زر "حاضر" أو "غائب" بجانب الطالب.
5.  يتم تحديث الحالة فوراً وإرسالها للمزامنة.

### 2. تدفق الاستئذان والخروج (Exit Flow)
1.  يطلب الطالب إذن خروج (لعيادة، إدارة، خروج نهائي).
2.  يدخل الموظف المختص لصفحة الخروج.
3.  يبحث عن الطالب بالاسم أو الرقم.
4.  يختار سبب الخروج ونوعه (مؤقت/نهائي).
5.  يحدد وقت العودة المتوقع (للخروج المؤقت).
6.  يضغط "طباعة تصريح" (Print Permit).
7.  عند عودة الطالب، يتم مسح الباركود مرة أخرى لتسجيل "عودة" (Return) وإغلاق التصريح.

### 3. تدفق المزامنة (Sync Flow)
1.  **حدث (Trigger):** عند إجراء أي تعديل (حضور، تعديل بيانات) أو دورياً كل دقيقة.
2.  **رفع البيانات (Push):**
    *   يجمع النظام السجلات غير المتزامنة (`synced: false`).
    *   يرسلها لـ Supabase عبر API (`upsert`).
    *   عند النجاح، يحدّث الحالة المحلية إلى `synced: true`.
3.  **جلب البيانات (Pull):**
    *   يطلب النظام التحديثات من Supabase التي حدثت بعد آخر مزامنة.
    *   يدمج البيانات الجديدة مع البيانات المحلية.
    *   في حالة التعارض، الأولوية للخادم (Server-wins) أو للأحدث زمنياً (Last-write-wins) حسب الإعداد.
4.  **تحديث الواجهة:** تنطلق أحداث (Events) لتحديث العدادات والجداول فوراً.

### 4. تدفق التقارير (Reports Flow)
1.  يدخل المدير للوحة التحكم (Dashboard).
2.  يتم تجميع البيانات محلياً من السجلات المخزنة لعرض الإحصائيات الفورية.
3.  للحصول على تقارير تفصيلية:
    *   يختار المدير الفترة الزمنية (يوم، أسبوع، شهر).
    *   يختار نوع التقرير (غياب، تأخير، مخالفات).
    *   يقوم النظام بتوليد ملف PDF أو Excel بناءً على البيانات وتمكين التنزيل.

### 5. تدفق الدخول والصلاحيات (Auth Flow)
1.  يدخل المستخدم اسم المستخدم وكلمة المرور.
2.  يتحقق النظام من صحتها (Hash Verification).
3.  يتم إنشاء جلسة (Session) وتخزينها محلياً.
4.  يتم توجيه المستخدم للصفحة المناسبة لدوره (مثلاً: المراقب -> صفحة المراقبة مباشرة).
